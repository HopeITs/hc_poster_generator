# خطوات الانتقال من Resend إلى خادم المؤسسة

## الوضع الحالي — ما تم التحقق منه

| البند | القيمة |
|---|---|
| خادم الاستضافة | `s1893.sureserver.com` → `195.42.143.64` |
| خادم البريد | `mail.hcsyria.org` → **نفس الـIP** |
| سجل MX | يشير إلى `mail.hcsyria.org` ✅ |
| إدارة الـDNS | `ns1/ns2.s1893.sureserver.com` — نفس اللوحة |
| منفذ 465 | مفتوح، TLS 1.3، `AUTH LOGIN PLAIN` |
| منفذا 25 و 587 | مغلقان من الخارج |
| سجلات TXT | **لا يوجد أي سجل — لا SPF ولا DKIM ولا DMARC** |

**سبب فشل الإرسال:** `/notify` كان يرسل من `onboarding@resend.dev`، وهو عنوان
اختبار لدى Resend لا يوصل إلا إلى بريد صاحب الحساب. المستلمان على نطاقين
مختلفين، فرُفض الإرسال. المشكلة لم تكن في الاستضافة.

**ما لا نحتاجه:** تنصيب Postfix، توليد DKIM يدوياً، طلب PTR، تسخين IP.
الخادم يعمل ولديه سمعة قائمة.

## الخطوة ١ — إنشاء صندوق البريد

**من:** أنت · **المكان:** لوحة الاستضافة ← Email Accounts

أنشئ: `no-reply@hcsyria.org` بكلمة سر قوية.

**المطلوب:** لا شيء مسبقاً.
**التحقق:** سجّل دخول إلى webmail بالحساب الجديد وتأكد أنه يفتح.
**أبلغني:** «تم إنشاء الصندوق» — لا ترسل لي كلمة السر.

---

## الخطوة ٢ — سجلات DNS

**من:** أنت · **المكان:** نفس اللوحة ← Zone Editor

| النوع | الاسم | القيمة |
|---|---|---|
| TXT | `@` | `v=spf1 a mx ip4:195.42.143.64 ~all` |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:postmaster@hcsyria.org` |

ثم من صفحة **Email Deliverability** فعّل DKIM وانشر السجل الذي تولّده.

**لماذا الآن:** أحد المستلمين على Gmail، وGmail يرفض أو يصنّف كـSpam البريد
غير الموثّق. هذه الخطوة ليست تحسيناً اختيارياً.

**التحقق:** بعد ١٥–٦٠ دقيقة، أخبرني وسأفحصها.
**أبلغني:** «تم نشر السجلات».

## الخطوة ٣ — رفع خدمة التحويل

**من:** أنت · **المكان:** File Manager أو FTP

ارفع الملفين من مجلد `mailer/` إلى مسار غير متوقَّع تحت الموقع، مثلاً
`public_html/_relay/`:

- `send.php`
- `config.php` — انسخه من `config.example.php` واملأه

**توليد السر:**

```bash
openssl rand -hex 32
```

املأ `config.php`:

```php
return [
    'secret'     => '<الناتج أعلاه>',
    'from_email' => 'no-reply@hcsyria.org',
    'from_name'  => 'Hope Center',
];
```

**المطلوب مني:** رابط الوصول فقط، مثل
`https://hcsyria.org/_relay/send.php`

**لا ترسل لي السر ولا كلمة سر الصندوق.**

## الخطوة ٤ — اختبار خدمة التحويل وحدها

**من:** أنت (لأن السر عندك)

```bash
curl -sS -X POST "https://hcsyria.org/_relay/send.php" \
  -H "Content-Type: application/json" \
  -H "X-Auth: <السر>" \
  -d '{"to":["بريدك@example.com"],"subject":"اختبار","html":"<b>مرحبا</b>"}'
```

**النتيجة المتوقعة:** `{"ok":true,"recipients":1}` ووصول الرسالة.

| الخطأ | المعنى |
|---|---|
| `401 unauthorized` | السر مختلف بين الطلب و `config.php` |
| `502 mail() failed` | الـMTA رفض — راجع سجل البريد باللوحة |
| `404` | المسار خاطئ |
| صفحة PHP خام | الاستضافة لا تنفّذ PHP في هذا المجلد |

**أبلغني:** الناتج الحرفي، وهل وصلت الرسالة وأين (الوارد أم Spam).

## الخطوة ٥ — ضبط أسرار الـWorker ونشره

**من:** أنا، بعد نجاح الخطوة ٤

```bash
cd worker
wrangler secret put MAIL_SECRET      # ستُدخله أنت تفاعلياً
wrangler secret put MAIL_ENDPOINT
wrangler deploy
```

`wrangler secret put` يطلب القيمة تفاعلياً ولا تظهر لي ولا تُحفظ في المستودع.

**لماذا هذا الترتيب:** الـWorker المعدّل يرفض العمل إن لم يجد
`MAIL_ENDPOINT` و `MAIL_SECRET`. نشره قبل جاهزية الخدمة يجعل `/notify`
يفشل فوراً.

---

## الخطوة ٦ — اختبار كامل من التطبيق

**من:** أنت · أنا أراقب

أنشئ بوستراً واضغط إرسال. أراقب أنا في نفس اللحظة:

```bash
wrangler tail --name studyzone-auth --format pretty
```

**التحقق:** وصول الرسالة بالمرفقات إلى المستلمَين، وظهور `ok:true` في السجل.

لن أشغّل `/notify` بنفسي لأنه يرسل بريداً إلى أشخاص حقيقيين.

---

## الخطوة ٧ — التنظيف

**من:** أنا

```bash
wrangler secret delete RESEND_API_KEY --name studyzone-auth
```

ويمكنك عندها إغلاق حساب Resend.

## ملخص ما تحتاجه مني وما أحتاجه منك

| الخطوة | يقوم بها | المعلومة المطلوبة |
|---|---|---|
| ١ صندوق البريد | أنت | — |
| ٢ سجلات DNS | أنت | — |
| ٣ رفع الملفات | أنت | رابط `send.php` |
| ٤ اختبار الخدمة | أنت | ناتج الأمر |
| ٥ الأسرار والنشر | أنا | تدخل السر تفاعلياً |
| ٦ اختبار كامل | أنت + أنا | — |
| ٧ التنظيف | أنا | — |

**لن أطلب منك أبداً:** كلمة سر صندوق البريد، السر المشترك، أو أي مفتاح API.

## سؤال مفتوح

هل «خادم المؤسسة» هو `195.42.143.64` نفسه، أم جهاز آخر منفصل؟
كل ما سبق مبني على أنه نفسه. إن كان هناك خادم آخر، أعطني عنوانه وسأفحصه
وأعدّل الخطة — وقد تحتاج عندها خطوات PTR وSPF مختلفة.
