# مفاتيح API — ربط برامج أخرى بالـAPI

الـAPI في `api/` يقبل نوعين من الدخول:

| الطالب | كيف يدخل |
|---|---|
| واجهة البرنامج في المتصفح | كوكي جلسة `HttpOnly` كما كان |
| برنامج آخر (خادم، سكربت، أتمتة) | **مفتاح API** في رأس الطلب |

المفتاح يعمل **بصلاحيات صاحبه الحالية**. لو تغيّر دور صاحبه أو حُذف حسابه،
تغيّر المفتاح معه أو بطل.

---

## إنشاء مفتاح

من جلسة متصفح مسجّلة الدخول (owner أو admin أو comms). لا يستطيع مفتاح
أن ينشئ مفتاحاً آخر.

```
POST /api/keys/add
{"name": "Zapier", "scope": "read", "days": 90}
```

- `name`: اسم البرنامج، ليُعرَف في القائمة.
- `scope`: `read` (طلبات GET فقط) أو `write` (كل الطلبات). الافتراضي `read`.
- `days`: مدة الصلاحية، من 1 إلى 3650. احذفه لمفتاح بلا انتهاء.

الرد يحوي `key` مثل `pgk_0ef4…`. **يظهر مرة واحدة فقط**، فالخادم لا يحفظ
إلا بصمته (SHA-256). إن ضاع المفتاح فألغِه وأنشئ غيره.

الحد الأقصى 10 مفاتيح لكل مستخدم.

## استعماله

```bash
curl https://hcsyria.org/api/projects -H "Authorization: Bearer pgk_..."
```

أو `X-API-Key: pgk_...` إن كان البرنامج لا يرسل `Authorization`.

## القائمة والإلغاء

```
GET  /api/keys                 ← owner يرى الكل، والباقون مفاتيحهم
POST /api/keys/delete {"id": 3} ← يتوقّف المفتاح فوراً
```

---

## ما لا يستطيعه المفتاح، عمداً

- **إنشاء مفاتيح** (`/keys/*`)، و**إنشاء مستخدمين** (`/users/add`)،
  و**تعيين كلمات السر** (`/users/set-password`). هذه بجلسة متصفح فقط.
  مفتاح مسرَّب ينشئ حساباً أو كلمة سر كان سيترك باباً يبقى مفتوحاً بعد إلغائه.
- **الطلب من متصفح على نطاق آخر.** لا رؤوس CORS، فالمفتاح للاستعمال
  من خادم لا من صفحة ويب. وضع المفتاح في JavaScript صفحةٍ عامة يكشفه للجميع.

## الأخطاء

| الرمز | المعنى |
|---|---|
| 401 `مفتاح API غير صالح` | مفتاح خاطئ أو ملغى |
| 401 `انتهت صلاحية مفتاح API` | تجاوز `days` |
| 403 `هذا المفتاح للقراءة فقط` | مفتاح `read` في طلب غير GET |
| 403 `هذه العملية تتطلب تسجيل الدخول من المتصفح` | عملية محصورة بالجلسة |

## التركيب على خادم قائم

الجدول جديد. شغّل المخطط مجدداً، فهو `CREATE TABLE IF NOT EXISTS` ولا يلمس
الجداول الموجودة:

```bash
mysql -u USER -p DBNAME < docs/mysql-schema.sql
```

`api/.htaccess` يمرّر رأس `Authorization` إلى PHP، لأن Apache مع FastCGI
يحذفه افتراضياً.
