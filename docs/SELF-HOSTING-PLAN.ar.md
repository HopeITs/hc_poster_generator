# خطة الانتقال الكامل إلى خادم المؤسسة

الهدف: إنهاء الاعتماد على Cloudflare (Workers + D1) وResend وcdnjs،
ونقل كل شيء إلى `195.42.143.64`، مع إغلاق الثغرات الأمنية المتبقية.

---

## الوضع الحالي

| المكوّن | أين هو الآن | إلى أين |
|---|---|---|
| واجهة المستخدم | `index.html` على الاستضافة | تبقى / Laravel |
| المصادقة والصلاحيات | Cloudflare Worker | PHP على خادمنا |
| قاعدة البيانات | Cloudflare D1 | MySQL على خادمنا |
| البريد | Resend | الـMTA المحلي |
| `html2canvas` | cdnjs | ملف محلي |

**بيانات حيّة:** 7 مستخدمين · 5 مشاريع · جلسات فعّالة · صور شخصية.

## الثغرات: ما ينحلّ بالانتقال وما لا ينحلّ

| الثغرة | الحالة الآن | بعد الانتقال |
|---|---|---|
| التوكن في `localStorage` | مخفّفة بـCSP فقط | **تُحَل** — كوكي `HttpOnly` من نفس الأصل |
| `Access-Control-Allow-Origin: *` | مفتوح للجميع | **يُلغى** — لا CORS أصلاً |
| `connect-src` لنطاقات خارجية | مطلوب | **يُشدَّد** إلى `'self'` |
| `cdnjs` كطرف ثالث | مخفّف بـSRI | **يُلغى** — ملف محلي |
| CSRF | غير موجود (لا يُستغَل مع Bearer) | **يصبح مطلوباً** — Laravel يوفّره |
| تهريب المخرجات | يدوي عبر `esc()` | **بنيوي** — Blade يهرّب تلقائياً |
| حظر محاولات الدخول | مُنفَّذ في الـWorker | يُنقَل — `throttle` جاهز |

### ثغرات جديدة يُدخِلها الانتقال

| الخطر | التخفيف |
|---|---|
| كشف `.env` | جذر المستند على `/public` — **بند حاسم في المرحلة ٠** |
| `APP_DEBUG=true` في الإنتاج | `.env` مضبوط + فحص بعد النشر |
| سلسلة تبعيات Composer | `composer audit` دورياً |
| **فقدان حماية Cloudflare** | حالياً الـWorker خلف حافة Cloudflare (DDoS/WAF مجاناً). بعد الانتقال كل شيء على جهاز واحد بلا واجهة حماية. |

> **الأهم:** بعد الانتقال يصبح `195.42.143.64` نقطة فشل وحيدة لكل شيء:
> الموقع والبريد وقاعدة البيانات والمصادقة. هذه مقايضة حقيقية مقابل
> الاستقلالية — قرار يخصّك، لكن يجب أن يكون واعياً.

## المرحلة ٣ — بناء Laravel بالتوازي

يُبنى على نطاق فرعي مثل `app.hcsyria.org` **دون لمس النظام العامل**.

- Breeze/Fortify للمصادقة · Policies للأدوار الأربعة
- جداول: `users`, `projects`, `user_projects`, `sessions`, `login_attempts`
- الصور الشخصية: `Storage` بدل عمود نصّي في قاعدة البيانات
- `Mail::` عبر الـMTA المحلي — بلا وسيط HTTP، فتسقط `mailer/send.php`

المحرّر والمعاينة والتصدير **تبقى JavaScript كما هي** — Livewire غير مناسب
لمعاينة تتحدّث مع كل ضغطة زر، وتوليد الصور يجب أن يبقى في المتصفح.

## المرحلة ٤ — نقل البيانات

```bash
wrangler d1 export studyzone-db --remote --output d1-final.sql
```

ثم تحويل SQLite → MySQL واستيراد.

### كلمات السر — النقطة الحسّاسة

الحالي: PBKDF2 بـ100000 دورة. Laravel يستخدم bcrypt.
**التحويل مستحيل رياضياً** — الهاش لا يُفَك.

ثلاثة خيارات:

| الخيار | الأثر |
|---|---|
| إجبار الجميع على إعادة التعيين | 7 مستخدمين فقط — مقبول، لكنه إزعاج |
| هاشر مخصّص يبقي PBKDF2 للأبد | يعمل، لكن يورّث تعقيداً دائماً |
| **إعادة الهاش عند أول دخول** ✅ | لا إزعاج، والانتقال يكتمل تلقائياً |

الخيار الثالث: عمود `legacy_password` يحمل هاش PBKDF2. عند الدخول، إن فشل
bcrypt ووُجد `legacy_password`، تحقّق بـPBKDF2 ثم أعد الهاش بـbcrypt وامسح
العمود. بعد دخول الجميع مرة واحدة، احذف العمود والكود.

### الجلسات

**لا تُنقَل.** الجلسات الحالية توكنات في `localStorage`، والجديدة كوكيز.
الجميع يسجّل دخولاً مرة واحدة — وهذا هو المطلوب أصلاً، فهو ما يُغلق الثغرة.
